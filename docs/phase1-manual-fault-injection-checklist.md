# Cue Phase 1 実機障害試験チェックリスト

更新日: 2026-08-28

## 目的

実際の会議キャプチャ中にCodex、音声デバイス、macOS権限の障害を発生させ、文字起こしの継続性、UIの応答性、自動復旧、復旧案内を確認します。

権限取消やBluetooth切断は端末の状態を変更するため、このチェックリストはユーザー立ち会いで実施します。

## 事前準備

1. `build/Cue.app`を起動する。
2. 任意のProject Rootを選ぶ。
3. Zoom以外の確認用として、QuickTime Player、ブラウザ、またはローカル音声ファイルで日本語音声を連続再生する。
4. Cueで会議を開始し、共有対象を選ぶ。
5. 相手側（システム音声）と自分側（マイク）の文字起こしが増えることを確認する。
6. 必要に応じて別のターミナルでログを表示する。

```sh
log stream --style compact --predicate 'subsystem == "jp.cue.app"'
```

## 共通の合格条件

- UIが固まらず、会議終了操作ができる。
- 障害のない音声系統の文字起こしが継続する。
- 復旧後、新しい確定文字起こしが60秒以内に追加される。
- 同じ確定文字起こしが重複生成されない。
- Codex障害中もローカルEvent Detectorが可能な範囲で動作する。
- 古いDeep Analysis結果を現在の話題として表示しない。
- 原因と復旧手順がUIに表示される。
- 会議終了後の診断でキューが増え続けず、ドロップ、復旧回数、エラーが確認できる。

## A. Codex障害

### A-1. Codexプロセス強制終了と自動再接続

1. Cueが「Read-Only接続済み」になっていることを確認する。
2. ターミナルで対象候補を表示する。

```sh
pgrep -fl 'codex.*app-server'
```

3. Cueが起動したCodex app-serverのPIDを1件だけ特定し、そのPIDを終了する。

```sh
kill <PID>
```

4. 「分析失敗」または「自動再接続待機中」が表示され、その後「Read-Only接続済み」へ戻ることを確認する。
5. 障害発生中も文字起こしが増えることを確認する。

### A-2. 応答停止、タイムアウト、復帰

1. A-1と同じ方法でCueのCodex app-server PIDを特定する。
2. プロセスを一時停止する。

```sh
kill -STOP <PID>
```

3. 手動分析を実行し、Fast分析は約8秒、Deep分析は約45秒でタイムアウトしてUI操作が継続できることを確認する。
4. プロセスを再開する。

```sh
kill -CONT <PID>
```

5. 自動再接続または手動の再接続後に分析できることを確認する。

### A-3. 長時間Deep Analysisのキャンセル

1. Deep分析を開始する。
2. 完了前に会議を終了する。
3. 分析状態が`cancelled`になり、終了後にカードが追加されないことをMeeting Reviewと保存データで確認する。

不正JSONは自動テスト`CodexAppServerClientTests.rejectsInvalidCardJSON`で確認済みです。

## B. 音声・会議アプリ障害

### B-1. マイク／入力デバイス切替

1. 会議中に「システム設定 ＞ サウンド ＞ 入力」で別の入力デバイスへ切り替える。
2. 切替中もUIが固まらないことを確認する。
3. 元の入力へ戻し、自分側の文字起こしが60秒以内に再開することを確認する。

### B-2. Bluetooth切断／再接続

1. Bluetoothマイクまたはヘッドセットを入力に選ぶ。
2. 会議中にBluetooth接続を切断する。
3. UIのエラー／復旧案内と、システム音声側の継続を確認する。
4. 再接続し、必要なら共有対象を再選択して、自分側の文字起こしが再開することを確認する。

### B-3. システム音声停止／復帰

1. 再生中の音声を60秒以上停止する。
2. 無音を障害として誤判定して再起動ループしないことを確認する。
3. 再生を再開し、相手側の文字起こしが60秒以内に再開することを確認する。

### B-4. Zoom起動／終了または共有対象アプリ終了

1. Zoomまたは現在の共有対象アプリを起動し、共有対象として選ぶ。
2. 共有対象アプリを終了する。
3. Cueがクラッシュせず、共有対象の再選択案内を表示することを確認する。
4. 対象アプリを再起動して共有対象を再選択し、文字起こしが再開することを確認する。

## C. macOS権限

### C-1. Microphone権限取消／再許可

1. 会議中に「システム設定 ＞ プライバシーとセキュリティ ＞ マイク」を開く。
2. Cueの許可を取り消す。
3. 自分側の停止、UIの原因表示、マイク設定・デバイス確認・会議再開始の案内を確認する。
4. 許可を戻し、macOSから求められた場合はアプリを再起動する。
5. 会議を再開始し、自分側の文字起こしが再開することを確認する。

### C-2. Screen Recording権限取消／再許可

1. 会議中に「システム設定 ＞ プライバシーとセキュリティ ＞ 画面収録」を開く。
2. Cueの許可を取り消す。
3. キャプチャ停止、UIの原因表示、画面収録設定・共有対象再選択の案内を確認する。
4. 許可を戻し、macOSから求められた場合はアプリを再起動する。
5. 会議を再開始し、相手側の文字起こしと画面OCRが再開することを確認する。
