# 話者分離・声紋照合の設計方針

最終更新: 2026-08-28

## 結論

Cueでは、PC音声を声質に基づいて「話者A・B・C」のように分離し、その話者埋め込みを登録済み参加者の声紋と照合する。ただし、照合結果は本人確認や認証には使わず、文字起こしへ名前を付けるための候補として扱う。候補名、信頼度、根拠区間を表示し、利用者が確定・修正できることを必須とする。

AppleのSpeechフレームワークは文字起こしと発話検出を提供し、Sound Analysisは音の種類を分類するが、人物単位の話者分離・声紋照合を標準機能として提供していない。そのため、Cue独自の参加者IDとローカル推論モデルを組み合わせる。

- [Apple Speech](https://developer.apple.com/documentation/speech/)
- [Apple Sound Analysis](https://developer.apple.com/documentation/soundanalysis)

## 採用候補

[FluidAudio v0.15.6](https://github.com/FluidInference/FluidAudio/releases/tag/v0.15.6)を第一候補とする。SwiftとCore MLでローカル実行でき、オフライン話者分離、話者埋め込み、既知話者の登録に対応する。ライブラリはApache-2.0であり、Cueへ組み込む際は依存ライセンスとモデルライセンスを配布物に明記する。

モデルは初回利用時に明示操作でダウンロードし、保存場所、容量、ライセンスを画面に表示する。ネットワーク制限環境では手動配置を選べるようにする。

## 精度の読み方

話者分離の主指標はDER（Diarization Error Rate）で、話者の取り違え、発話の見逃し、誤検出を合算する。0%が完全一致であり、値が低いほど良い。

FluidAudioの公開ベンチマークでは、オフライン処理の平均DERはVoxConverseで約13.9〜15.1%、AMI会議データで約10.6%と報告されている。一方、ストリーミング処理はオフラインより不安定と明記されている。これらは公開データセット上の値であり、Zoomの圧縮音声、似た声、同時発話、短い相づち、BGM、スピーカーからの回り込みでは精度が下がる可能性がある。

声紋照合用のCAM++公開評価には、クリーンな読み上げ音声でEER 0.48%という結果がある。ただし、実会議・日本語・Zoom経由の本人照合精度を保証する値ではない。Cueでは実際の利用条件で別途評価する。

- [FluidAudio diarization guide](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Diarization/GettingStarted.md)
- [FluidAudio benchmarks](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md)

## 実装段階

1. 参加者マスターと会議名簿
   - 参加者に恒久IDを付与する。
   - 社内、外注、クライアント、その他を区分する。
   - 全プロジェクト共通、複数プロジェクト、単一プロジェクトの範囲を持つ。
   - 会議開始前に参加予定者を選び、会議記録へスナップショット保存する。
2. 会議後のオフライン話者分離
   - PC音声を16kHz・モノラルへ正規化して処理する。
   - 初期版では高品質なオフライン処理を優先する。
   - 話者クラスタ単位で文字起こし区間をまとめ、一括で名前を割り当てる。
3. 声紋の登録と照合
   - 利用者が選んだ、雑音や同時発話の少ない区間だけを登録候補にする。
   - 埋め込みは端末固有鍵で暗号化し、鍵はKeychainに保存する。
   - 生音声を保存しない設定でも、利用者が承認した埋め込みだけを恒久保存できるようにする。
   - 削除、再登録、登録日時、モデルバージョン、サンプル数を管理する。
4. 信頼度と人による確定
   - 自動割り当ては十分な発話長と閾値を満たす場合だけ候補表示する。
   - 上位候補との差が小さい場合は「不明」のままにする。
   - 利用者の修正を会議記録へ保存し、未承認の結果を確定情報としてAI要約へ渡さない。

## 品質ゲート

- 公開ベンチマーク値をCueの実測値として表示しない。
- Zoom、Google Meet、対面スピーカー再生を含む実会議相当データでDERを測る。
- 登録済み話者について、正受入率、誤受入率、未判定率を分けて測る。
- 同姓同名ではなく参加者IDで保存し、表示名変更後も過去記録を追跡できるようにする。
- 推論失敗時も文字起こしと会議記録の保存を止めない。

## プライバシー

声紋は生体情報に準じて扱う。登録前の説明と同意、ローカル暗号化、個別削除、再登録、モデル削除を実装する。ポートフォリオ用の公開リポジトリ、テストデータ、スクリーンショットへ実在人物の音声・声紋・氏名を含めない。
